### RPF-02 — XLSX見出し規則

**調査結果（source由来。仕様採択ではない）**

Java `ProjectXlsxImport.toWorkbookJsonDocument` は `Tasks` / `Resources` / `Assignments` を `ProjectXlsxImportEntities.importTabularSheet` へ渡す。Java HEAD `c0b4421`のF-J5 implementationは、schema header文字列とheader row 2の値を完全一致で照合し、schema順に探索して最初に見つかった同名cellの列indexを採る。少なくとも1つknown labelがあれば欠落labelはmappingに作らず、未知labelはmappingへ入らない。known labelが0件の場合だけJava native schema列位置へfallbackする。行内cellが列位置まで無い場合、`readCell` は`null`を返す。

| sheet | Node共通header | Java-only header |
| --- | --- | --- |
| Tasks | `UID, ID, Name, OutlineLevel, OutlineNumber, WBS, Start, Finish, Duration, PercentComplete, PercentWorkComplete, Milestone, Summary, Critical, CalendarUID, Predecessors, Notes` | `Type, Priority, ConstraintType, ConstraintDate, Deadline` |
| Resources | `UID, ID, Name, Type, Initials, Group, MaxUnits, CalendarUID, StandardRate, OvertimeRate, CostPerUse, Work, ActualWork, RemainingWork` | `Cost, ActualCost, RemainingCost, PercentWorkComplete, WorkGroup, StandardRateFormat, OvertimeRateFormat` |
| Assignments | `UID, TaskUID, TaskName, ResourceUID, ResourceName, Start, Finish, Units, Work, ActualWork, RemainingWork, PercentWorkComplete` | `StartVariance, FinishVariance, Delay, Milestone, WorkContour, Cost, ActualCost, RemainingCost, OvertimeWork, ActualOvertimeWork` |

Calendars / NonWorkingDaysは同じJava `importTabularSheet` helperを使うが、別schema/別sheetである。Projectは`Field` / `Value`の固定列で読む特殊処理。これらをTasks/Resources/Assignmentsの境界回帰へ含めない。

| case | Java sourceで確認した現在挙動 | 下流・public API上の帰結、要確認点 |

### RPF-04 — F-S5 patch入力とprojection出力

`update_task`の入力規則はAI projectionの出力形と別の契約である。AI spec 474–476行は`notes` / `calendar_uid`空文字を明示的にclear、unknown `calendar_uid`をwarningで無視すると記す。Node `project-patch-json-updates.ts` はfield省略時に代入せず、空文字でnotesを`undefined`、calendar UIDを`undefined`へclearし、JSON null等の非stringをwarningにする。unknown calendar UIDもwarningで変更しない。既存update-patchのfixture/testはNode実装の支えであり、Java parityの根拠ではない。

Javaは`ProjectPatchJsonCore.importProjectPatchJson`のop dispatchを確認した。dispatchに`update_project`, `update_assignment`, `update_resource`, `update_calendar`はあるが`update_task`は無い。Java `ProjectPatchJsonUpdates`にもtask update methodは無い。したがってJavaの`update_task.notes/calendar_uid`値別の実装・test・観測結果は「未実装／未確認」とする。field名が他の`PatchOperation`やAI projectionにあることはdispatch対応の根拠にならない。

| field/value | AI JSON spec | Node patch `update_task` | Java patch `update_task` | projection output / 実測 |
| --- | --- | --- | --- | --- |
| notes omitted | omitted input means field is not supplied; patch prose does not change the stored value | `fields.notes === undefined`; unchanged | `update_task` dispatch missing; no field path | task-edit未設定時Nodeは省略、Javaは空文字。これは生成AI編集入力への明示値変換規則ではない |
| notes null | JSON type contract requires string when supplied | non-string warning, no mutation | dispatch missing; untested | projection未設定形のNode省略とJava空文字は別観測 |
| notes empty string | spec says clear | stores `undefined` | dispatch missing; existing behavior unknown | AI projectionの空文字を入力clearと結び付ける実装根拠なし |
| notes string | spec says update | assigns the value | dispatch missing; candidate test needed if adopted | output is state/model-derived |
| calendar_uid omitted | not supplied | unchanged | dispatch missing | task-edit Node emits `null`, Java emits `""` for unset |
| calendar_uid null | supplied type should be string | non-string warning, no mutation | dispatch missing; untested | projection's `null` is not evidence that patch input `null` clears |
| calendar_uid empty string | spec says clear task-specific calendar | clears to `undefined` | dispatch missing; existing behavior unknown | separate projection serialization decision |
| calendar_uid known UID | must identify existing calendar | updates | dispatch missing | current state can project value |
| calendar_uid unknown UID | spec says warning and ignore | warns, no mutation | dispatch missing; no behavior established | no projection consequence specified |

既存LEG-J14の同一state出力とlocal MCP/Skills consumer調査は、task-edit projectionがartifact/stdoutとして渡り、既知consumerがfield shapeを正規化する根拠は確認できなかったことを示す。外部consumerは未確認。従ってF-S5は「patch input contract is existing text/spec+Node path (Java update_task support is a separate implementation gap); projection unset output representation remains undecided」と分ける。後続候補: Java patch op dispatchとtask field updates/testsを追加するか採択する前に、field-specific compatibility impact and scope is separately reviewed. 本カードでは追加実装をしない。
